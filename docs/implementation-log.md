## 2026-07-24 v2.3 CPU 戦略層（本人フィードバック: 自滅回避・判定録からの逆算・ライフ分散）

- **自滅の機械的防止** `decideAttack`（rooms/cpu.ts）: 攻撃を生成 → 自分の残ライフとの関連度を実採点で自己検査 → 破壊圏（>= destroyThreshold）なら 1 案目を禁止語に足して作り直し → 2 案とも危険なら自滅リスクの低い方。プロンプト頼みにしない
- **判定録からの逆算** `collectClues`（rooms/room.ts）: 相手の未破壊 SECRET ごとに「過去の攻撃語 × 関連度」を集め、攻撃プロンプトに手掛かりとして渡す。「60 前後なら惜しい・その近傍のまだ試していない角度を突く」と指示。序数照合は現在の open 数 + secrets 元位置（allSecret では安定、legacy はヒューリスティック許容と明記）
- **ライフの分散** `candidatePairScores` + `decidePick` 拡張: CPU 選抜前に候補同士の関連度をペア採点（≤9 候補で 36 ペア・LRU キャッシュ共有）し、貪欲法で「選択済みとの最大関連度が最小」の候補を足していく。1 つの攻撃で複数ライフが同時に壊れない組を選ぶ。人間側対策として概念生成プロンプトにも相互分散の要求を追加
- Scorer.generateAttack に `intel`（ownLives + clues）を追加。demo/Resilient は自ライフ同一語を禁止語扱い。テスト 6 件追加（分散貪欲・自己検査 4 パターン・プロンプト内容）で 206 tests green
- 本番検証（テーマ「羽根×静寂」）: 自滅なし・攻撃のターン間多様化・clue 逆算の方向転換（風 55 → 雲/さざ波で近傍 40 を詰める）を確認。**同ターンに複数 CPU が同語「風」を出す並行生成 race を発見** → 提出直前に重複チェック + 1 回作り直しを追加して修正

## 2026-07-25 v2.4 仮説駆動 CPU（本人の対局 R6CNDQ の全ターン分析起点）

- 分析（エアロバイク×農作業者・15 回合）で確定した v2.3 の失敗 4 点: ① 攻撃 15 本中 11 本が農系の言い換え（avoid は文字列一致のみで接尾辞違いが素通り）② 1v1 終盤 6 連続で「全部 30 以下 = その領域ではない」という除外情報を無視 ③ r1 で CPU・北が自ライフ「野菜」に 85 の「トラクター」を投げ自滅（「2 案とも危険なら低リスク採用」の妥協が発動）④ CPU ライフが 1 ホップ連想ばかり（オートバイ等）で人間の遠い概念（Claude Code 等）は 11〜15 ターン生存
- **decideAttack を仮説駆動に全面書き換え**（rooms/cpu.ts）: 主標的 = 残りライフ最多の相手 → 手掛かりが最も「惜しい」秘ライフに対し `generateHypotheses`（新 Scorer メソッド）で相手概念を N=6 推測（低スコア領域の除外を明示指示）→ 各仮説 × 過去攻撃を実採点し観測値との平均絶対誤差で並べ替え（判定録を正解制約に使う三角測量）→ 自ライフに破壊圏で当たらない最有力仮説を攻撃に採用
- **自滅攻撃の完全排除**: 妥協ロジックを廃止。仮説全滅 → 従来生成 3 回 → それでも安全が無ければ中立プール（demo の CONCEPT_POOL）から実採点で最小リスク語。破壊圏の語は決して投げない
- **ライフ生成の目標を引き下げ**: CONCEPT_SYSTEM の目安を各テーマ 30〜55 → 20〜35（合計が選抜下限をわずかに超える遠さ）
- demo モードの `generateHypotheses` は空配列 = 従来の決定的挙動へフォールバック（テスト・E2E の再現性を維持。推理エンジンは LLM 採点時のみ有効）。コストは CPU 1 手あたり LLM 1〜2 呼び出し + 採点バッチ 2〜3（LRU 共有）
- テスト: 仮説の誤差順採用・危険仮説のスキップ・主標的の選択・フォールバック・自滅ゼロ保証など 209 tests green
- 本番検証（テーマ「雷鳴×深緑」）: 仮説エンジンの初手が即命中（CPU・南「雷雨」→ CPU・北「稲妻」95）、探査の固着なし（オーケストラ・光・嵐と領域が散る）、自滅ゼロ。**新バグ発見: 両 CPU がライフに同じ「苔」を選出**（概念生成の並行 race — 攻撃側 v2.3 と同型）→ 提出直前の重複チェック + 1 回作り直しで修正

## 2026-07-26 v2.5 選抜下限 50 + 温度勾配推理 + ライフ検品（本人の対局 KQ2A9U の分析起点）

- 分析（桜風×メロディー・9 回合・本人勝利）で確定した 3 課題: ① 下限 30 ではテーマ無関係語（MCP・サブスクリプション）が実質無敵ライフ — 18 発の攻撃が一度も 55 を超えず推理ゲーム不成立 ② CPU 攻撃が広いカテゴリ語（幻想→空→音色→旅→風景→心地）ばかりで 30〜50 に頭打ち。破壊した攻撃（淡色 80・氷 70・写真 70）は全て具体語 ③ CPU ライフがまた 1 ホップ（リズム・楽器・楽譜）で「文化」1 発 2 枚破壊 — 目標帯 20〜35 をプロンプトだけでは生成 LLM が守らない
- **ルール**: `pickMinTotal` 既定 30→**50**、推奨式 テーマ数×15→**×25**（本人指示）。UI 文言・PickPanel フォールバックも更新。demo 採点は無関連 25×2=50 で境界ちょうど選抜可 — テスト・E2E 影響なし
- **攻撃の温度勾配推理**: HYPO_SYSTEM を書き換え — ヒントを 60+=熱い（近傍の具体物）/ 40〜59=ぬるい（同じ大領域の異なる具体物を掘る）/ 39-=冷たい（域除外）で読み、無手掛かりは「偵察」（未踏領域の具体物で切り分け）。**仮説・攻撃とも広いカテゴリ語（自然・文化・旅）を禁止**（70 に届かないため）
- **ライフ検品** `generateInspectedConcepts`（rooms/cpu.ts）: 生成候補を各テーマと実採点（LRU キャッシュにより本選抜 applyScores と同値）し、「1 ホップ語」（どれかのテーマと 60 以上）と「遠すぎ語」（合計 < pickMinTotal）を 1 回作り直しで置き換え。不足時は「選抜可能 → 近すぎない順」で必ず n 個埋める
