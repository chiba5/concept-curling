## 2026-07-24 テーマ多様化（本人フィードバック「テーマが毎回ほぼ同じ」）

- 原因: 採点用の temperature 0.2 が `callJson` 経由で生成系にも共有され、同一プロンプト低温で gpt-4o-mini が「夢」「風船」系ばかり返していた
- 修正: 生成系（テーマ・概念・攻撃）を temperature 1.0 に分離 + テーマはサーバ内 20 ジャンル（自然現象・道具・感情…）から毎回ランダム抽選してプロンプトに指定（低温でも構造的に散る二段構え）。採点の低温・決定性・キャッシュは維持
- 本番検証: ソロ 3 連続で「指先×調和」「旋律×海辺」「ウサギ×すごろく」— 夢/風船 への固着が解消

## 2026-07-24 v2.2 バランス調整 + CPU 知能化（本人フィードバック 3 点）

- ルール調整: 破壊 = 関連度 **70 以上**（既定 50→70、判定も「超」→「以上」に変更）/ 選抜 = 合計 **30 以上**（既定 50→30、推奨式テーマ数×15）
- CPU 知能化 3 点: ① 選抜を「合格圏で最も関連の低い概念」に反転（直接連想をライフにしない）② 攻撃 avoid リスト（過去攻撃・同ターン提出済み・破壊済み概念・テーマ語）③ プロンプト書き換え — 概念生成は同義語禁止 + 突飛な 2 ホップ連想（寂しさ→留守番電話）、攻撃は「相手が選びそうな中距離連想語を推測して狙う」（全 SECRET では攻撃対象が常にテーマへフォールバックしていた実装事情も明記）
- 本番検証（テーマ「雷光×抽象画」）: 90/100 は破壊・60 以下は不発（70 閾値 ✓）/ 合計 30 以上の選抜文言 ✓ / CPU 攻撃が 3 ターン連続で新語（稲妻→キャンバス→表現、閃光→色彩→スチル）✓
- 検証中に発見・即修正: CPU が自分の SECRET と同一語を攻撃に出し 100 で自滅（CPU・南「色彩」）→ 攻撃 avoid に自席の残ライフ概念を追加。同一語自滅は構造的に消えた（類似語の巻き添えは人間同様に残る仕様）

## 2026-07-24 v2.3 CPU 戦略層（本人フィードバック: 自滅回避・判定録からの逆算・ライフ分散）

- **自滅の機械的防止** `decideAttack`（rooms/cpu.ts）: 攻撃を生成 → 自分の残ライフとの関連度を実採点で自己検査 → 破壊圏（>= destroyThreshold）なら 1 案目を禁止語に足して作り直し → 2 案とも危険なら自滅リスクの低い方。プロンプト頼みにしない
- **判定録からの逆算** `collectClues`（rooms/room.ts）: 相手の未破壊 SECRET ごとに「過去の攻撃語 × 関連度」を集め、攻撃プロンプトに手掛かりとして渡す。「60 前後なら惜しい・その近傍のまだ試していない角度を突く」と指示。序数照合は現在の open 数 + secrets 元位置（allSecret では安定、legacy はヒューリスティック許容と明記）
- **ライフの分散** `candidatePairScores` + `decidePick` 拡張: CPU 選抜前に候補同士の関連度をペア採点（≤9 候補で 36 ペア・LRU キャッシュ共有）し、貪欲法で「選択済みとの最大関連度が最小」の候補を足していく。1 つの攻撃で複数ライフが同時に壊れない組を選ぶ。人間側対策として概念生成プロンプトにも相互分散の要求を追加
- Scorer.generateAttack に `intel`（ownLives + clues）を追加。demo/Resilient は自ライフ同一語を禁止語扱い。テスト 6 件追加（分散貪欲・自己検査 4 パターン・プロンプト内容）で 206 tests green
